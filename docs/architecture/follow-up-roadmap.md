# 后续分支计划

本文档只记录不适合继续压在当前修复分支里的事项。它们都需要跨模块改造、数据迁移，或者独立验收，不再混进本分支的修复范围。

## 本分支已收口

当前分支已经完成以下收口：

- RBAC 学校范围鉴权改为默认拒绝
- RBAC 管理写接口补齐业务校验、错误码和 4xx 归类
- 学生认证改为学校配置驱动，学籍表解析 fail-closed
- 学校级统一身份认证配置改成真实配置
- 学生认证复审状态补齐 `rejection_reason` 和 `reviewed_at`
- 评课访问学校范围和预览长度改成后台可配置

## 后续事项

| 事项                   | 当前状态                                                                    | 目标方案                                                                                                                                                       | 为什么不放在本分支                                                                             |
| ---------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| RBAC 跨请求权限缓存    | `GetEffectivePermissions` 仍然按请求查库，只有 Gin 请求内缓存               | 设计跨实例可用的 per-user 缓存。推荐使用 Redis 或本地缓存 + 版本号失效。角色、用户组、个人权限变更后，需要精准失效相关用户缓存                                 | 会影响 RBAC 全链路，牵涉角色、用户组、个人覆盖三类写路径和失效策略，需要独立压测               |
| 评课内容审核流水线     | 当前只有本地敏感词检查，`block` 会拦提交，`warn` 只检测不落状态             | 抽象统一审核接口，支持固定敏感词、AI 审查、云审核 Provider 串联执行。顺序建议为白名单免审 → 本地词库 → 外部 Provider。命中 `warn` 时要持久化标记、进入复核链路 | 需要新增审核状态字段、Provider 接口、后台复核页面和运维配置，改动面横跨评课、RBAC 和后台       |
| 应用级通知中心         | 现有通知接口暂挂评课模块，只支持拉取，仍沿用旧表结构                        | 独立 `notification` 模块，统一改成 `user_id` 归属键，提供 SSE 实时推送，并完成旧路由迁移和兼容期治理                                                           | 牵涉表结构迁移、匿名业务补 `owner_user_id`、OpenAPI 变更和前端全局接入，不适合塞进当前修复分支 |
| 认证方式与审批策略解耦 | 当前 `ldap` 成功即 `verified`，`manual` 提交即 `pending`                    | 为学校配置新增审批策略字段。统一身份认证和表单人工认证都能配置成自动通过或人工复核。无论自动还是人工，都保留完整审核记录和复审轨迹                             | 会改学校配置模型、学生认证状态机、管理端审核流和文案，需要单独验收                             |
| 实名自动匹配的多校化   | 大陆身份证实名里的 `academic_db_match` 仍然依赖默认学籍表，天然缺学校上下文 | 重新定义自动匹配入口。优先方案是在用户先选学校后再做实名匹配，或设计多校候选匹配流程，避免把默认学校逻辑继续扩散                                               | 这不是单点修补，先要定产品流程，再改实名接口、学籍查询和前端引导                               |

## 拆分建议

推荐按下面的顺序开后续分支：

1. **IAM 架构迁移**（Zitadel + OpenFGA）← **新增，最高优先级**
2. 认证方式与审批策略解耦
3. 实名自动匹配的多校化
4. 评课内容审核流水线
5. 应用级通知中心

原因是 IAM 迁移会重建整个身份和授权基础，后续所有涉及认证、权限、学校配置的工作都应基于新架构进行。"RBAC 跨请求权限缓存"在 IAM 迁移后自动解决（Token claim 自带角色，中间件内存展开，不再查 DB）。

详细方案见 [iam-architecture-design.md](iam-architecture-design.md)。
