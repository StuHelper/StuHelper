# logic-layer

## summary
The admission logic layer of join.stuhelper.com consists of five framework-free TS modules plus one form component. api.ts wraps the shared openapi client (api.admission) with 13 methods that strictly runtime-validate every response field (enums, integer-or-string IDs, absolute http(s) URLs, null/undefined distinctions) and throw exact English error strings. admissionState.ts maps backend session/me status to a 12-value page-state union with deliberately asymmetric ordering. admissionToken.ts handles return-URL hardening (/verify/:code same-origin only), error-code/message-regex classification of admission API errors, and sessionStorage persistence of linked session IDs keyed by token. projectionRefresh.ts is a bounded exponential-backoff (1s/2s/4s/8s/16s) poller waiting for the 'review:create' capability with full AbortSignal support. OldStudentVerificationFlow.vue implements school selection, school-SSO redirect, and a school-email-OTP flow with a 300ms-debounced, runID-race-guarded academic student-ID/name match that auto-derives the student email (BUAA policy). The five .ts modules are pure and reusable as-is; the .vue file entangles a six-state academic-match machine, trimming/reset semantics, and hardcoded zh-CN copy with markup that tests select via data-* attributes and DOM order.

## rewrite_risks
- State-mapping asymmetry trap: stateFromAdmissionSession checks joined_muted BEFORE projectionPending (a muted-joined session with projectionPending=true must show 'ready'), while stateFromAdmissionMe checks projectionPending FIRST and maps joined_muted to 'error'. Unifying these two functions 'for cleanliness' changes page states.
- Error-classification overlap: admission.token_expired is in both TERMINAL (→'expired' via mapAdmissionApiError) and EXPIRED_ADMISSION_SESSION sets, while admission.token_consumed is terminal but deliberately NOT 'session expired' — child flows (OTP, camera) must keep working on consumed tokens (oldStudentFlow.test.ts:226). Collapsing the three code sets into one breaks consumed-token resume.
- requireData throws three distinct shapes: raw transport error, raw envelope OBJECT (not Error) for {success:false}/{error}, and new Error for empty data. admissionToken's nested .error.code duck-typing and api.test.ts:124 (rejects.toEqual the raw object) depend on not normalizing these into a single Error class.
- Message-regex error detection: 'qq binding conflict' and 'camera handoff locked' are matched on free-text messages with generic code A0000409 — backend wording is the contract; do not switch to code-only detection.
- Race/cleanup machinery in academic match: 300ms setTimeout debounce + monotonically increasing runID guard applied on BOTH success and error paths, plus onBeforeUnmount bump.
