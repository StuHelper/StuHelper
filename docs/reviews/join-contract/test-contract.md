# test-contract

## summary
The admission slice (join.stuhelper.com) is a host-gated Vue 3 module under src/modules/admission with 6 logic files and 10 view components implementing: (1) the /verify/:code admission token page (AdmissionPage.vue) — a 12-state machine (loading/needsLogin/accountMismatch/qqMismatch/ready/linked/pendingReview/projectionPending/approved/invalid/expired/error) driven by GET/LINK admission-session APIs, with consumed-token resume, sessionStorage session memory, QQ bind-confirmation dialog, pendingReview backoff polling, and projection-capability refresh; (2) the freshman material flow (desktop camera capture + QR mobile handoff over SSE with polling fallback, plus a login-free mobile camera page at /admission/freshman/camera/:token); (3) the old-student flow (school SSO link-out + academic school-email OTP); (4) /start self-service readiness page embedding user-module panels; (5) join-domain host/path routing rules. Tests: 8 vitest files in the module (~120 assertions-heavy cases), 2 router test files, and 2 Playwright specs (auth-callback-and-admission.spec.ts fully, search-and-static.spec.ts join-host part), all running against an unmocked-API-500 stub dev server in BOTH desktop and Pixel-5 mobile projects, with fixtures that fail any test on console errors or unexpected 4xx/5xx. Tests select almost exclusively via data-* attributes (deliberate hooks), exact hardcoded Chinese copy, ARIA roles/labels, and a handful of CSS classes; preserving the data-* attributes, copy strings, and timing constants is the cheapest path to keeping all tests green.

## rewrite_risks
- Teleported dialog: admissionPageStates tests query document.body (getDialogElement), NOT the wrapper — the bind-confirmation dialog must keep rendering into body (current shadcn/reka Dialog behavior) with all four data-admission-bind-confirmation-* attributes; an inline modal would break every bind-flow test.

Any change to these numbers or to when timers are scheduled breaks tests.
- settleAdmissionPage budget: AdmissionPage must reach steady state within flushPromises x2 + one setTimeout(0) + nextTick. Introducing extra async hops (transitions, lazy child mounting, suspense, debounced loads) will make assertions observe intermediate states.
- Race-condition guards are individually tested and easy to lose in a rewrite: (a) stale-route guard after EVERY await in loadAdmissionSession (token changed mid-flight); (b) mobile page stale preview AND stale upload dropping after token change (incl. e2e popstate test); (c) SSE stale-source filtering after handoff regeneration (events from old EventSource must be ignored even though it was closed); (d) load serialization with single queued reload; (e) in-flight dedup on every mutating button (link, application+handoff, upload, continuation, OTP verify) implemented as disabled + internal flags — double-click tests use deferred promises.
- Auth-probe discipline: needsLogin must be derivable WITHOUT network calls when there is no session hint and no admission auth-return marker (bootstrapSession not called — unit test), and join-host public/error pages must generate ZERO /auth/me and /auth/refresh requests (e2e asserts counts with expect.poll). Eagerly bootstrapping auth in a rewritten page/layout breaks both.
- linkAdmissionSession must never send a qq parameter (three e2e tests capture the /link URL and assert qq===''); the typed-QQ confirmation is client-side only and must trim whitespace.

- Browser-event wiring: window 'pageshow' (incl. bfcache persisted flag), window 'focus', document 'visibilitychange' (hidden must PAUSE pendingReview polling; visible resumes/refreshes). Unit tests dispatch bare Event objects on window — listeners must be on window/document, not on the component root.
