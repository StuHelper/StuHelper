# verify-flow-views

## summary
AdmissionPage.vue is the /verify/:code (route name 'admission-token', router/index.ts:197-204, meta layout:'none') admission flow controller for join.stuhelper.com. It drives a 12-value state machine (AdmissionPageState in admissionState.ts:3-15: loading, needsLogin, accountMismatch, qqMismatch, ready, linked, pendingReview, projectionPending, approved, invalid, expired, error) rendered through a shared shell (AdmissionShell), a 4-step progress strip (AdmissionProgress), generic state panels (AdmissionStatePanel), a reissue-command hint (AdmissionReissueHint), and a projection-sync notice (ProjectionPendingNotice). It orchestrates token preview → auth probe → QQ-binding mismatch precheck → explicit bind confirmation (typed-QQ dialog) → linkAdmissionSession → flow tabs (old-student vs freshman) → pendingReview visibility-gated polling → capability-projection bounded retry → approved. It handles consumed tokens via sessionStorage-remembered session IDs, stale-route guards after every await, a single-flight reload queue, and pageshow/focus/visibilitychange browser-return refresh. All copy is hardcoded Chinese (no i18n), and unit + e2e tests assert heavily on data-* attributes, data-state values, exact Chinese strings, heading roles, and two CSS classes (.primary-button, .flow-tab).

## rewrite_risks
- Stale-route race handling: loadAdmissionSession re-checks isCurrentAdmissionRoute(requestToken) after EVERY await (AdmissionPage.vue:746,749,757,760) and resumeRememberedAdmissionSession does the same (611,620); plus the single-flight queue with reload-queued flag (783-795). Dropping any guard reintroduces the bug covered by test 'ignores stale admission loads' — a slow first token resolving late must not clobber the new token's state.
- Asymmetric status mapping order: stateFromAdmissionSession checks joined_muted BEFORE projectionPending; stateFromAdmissionMe checks projectionPending FIRST (admissionState.ts:17-40). Unifying these 'for cleanliness' changes behavior for joined_muted+projectionPending payloads.
- getAdmissionMe call-count contract: handleSessionState→loadLinkedResources(refreshAdmission:true) vs handleAdmissionMeState→loadLinkedResources(refreshAdmission:false) (561,587). Tests assert getAdmissionMe toHaveBeenCalledTimes(1) on both the consumed-token resume and remembered-session paths — a naive rewrite that always refreshes will double-fetch and fail tests.
- refreshAdmissionAuthState short-circuit order (634-638): consumeAdmissionAuthReturn DELETES its sessionStorage key when invoked; it must remain the last operand so it is not consumed when isAuthenticated or a session hint already short-circuits. Also bootstrapSession failure falls back to current auth.isAuthenticated, not false (642-646). Test asserts bootstrapSession is NOT called when no hint exists.
- PendingReview polling invariants (671-721): backoff [5s,10s,20s,30s] capped at last; gated on document.visibilityState==='visible'; single timer + in-flight flag; attempt counter reset only on (re)entry via the pageState watch (944-950) with reset=true; reschedule happens in finally only if still pendingReview; tab hidden clears the timer, tab visible/pageshow/focus triggers an IMMEDIATE refresh (clear timer first, 698-701). Unit test pins the first poll at exactly 5000ms and zero calls before — changing delays or adding an immediate first poll breaks it.
- Projection refresh abort semantics (649-664): each schedule aborts the previous AbortController; retry button re-schedules; unmount aborts; AbortError (DOMException name check, 960-962) must be swallowed while other rejections map through applyError. waitForAdmissionProjection's exact options object {refreshAuth: auth.fetchUser, signal} is asserted — wrapping fetchUser in a lambda breaks toHaveBeenCalledWith referential equality.
- Bind dialog UX edge cases: cannot close (cancel button, outside click, escape — all via handleBindConfirmationOpenChange/closeBindConfirmationDialog) while linking (862-874); input/touched reset on every open and on route change; QQ comparison trims both sides (whitespace-paste test); error only after blur(touched)+non-empty input; Enter key submits with .prevent; submit disabled state asserted via native HTMLButtonElement.disabled; dialog content queried from document.body (teleport) — replacing the Dialog primitive with a non-teleporting one keeps unit tests passing only by accident and changes e2e focus/escape behavior.
- Error containment in linked state: post-link getAdmissionMe/fetchSchools failure must keep [data-state=linked] visible with inline [data-linked-resource-error] + retry, NOT transition to global 'error' — but expired-class errors (token_expired/token_not_found/session_not_found) must still flip to 'expired' (544-557). Easy to flatten into a single error path during rewrite.
- Consumed-token tri-state: token_consumed on preview → (a) logged out: needsLogin with alternate copy and NO 注册 button (consumedTokenNeedsLogin flag also changes statusLabel to '等待原账号登录'), (b) logged in + relink succeeds: silent resume, (c) relink throws token_consumed again: accountMismatch (756-778). Plus the remembered-sessionStorage fast path that must forget the key and FALL THROUGH (return false) on non-expired errors (623-630).
- qqMismatch precheck (565-579) only runs for joined_muted sessions with a qqID and swallows fetchQQBinding failures; it intercepts BEFORE showing 'ready', preventing the user from ever seeing 开始认证 — tests assert linkAdmissionSession is never called in this path.
- Flow-tab defaulting interplay (498-538): setAdmissionMe force-switches to oldStudent when credentialKind is school_sso/school_email_otp (also hides FreshmanCameraFlow in favor of [data-formal-student-credential]); syncDefaultAdmissionFlow prefers oldStudent only if some ENABLED school has SSO/OTP; manual tab choice sticks until route.fullPath changes. Order of setAdmissionMe (which may force oldStudent) vs syncDefaultAdmissionFlow matters.
- Selector/markup coupling: unit tests use 'button.primary-button' and '.flow-tab' CSS classes (markup-coupled — the ONLY two class-based hooks; renaming them requires test updates) and e2e uses getByRole('heading') for panel titles (must stay h1-h6) and getByText('QQ：123456') for the shell fact format (full-width colon '：' is load-bearing). All data-* attributes must be carried over verbatim.
- data-state value collision: AdmissionPage's [data-state=ready] (joined_muted panel) vs FreshmanCameraFlow/mobile camera's [data-state=ready|uploaded|mobile] on other routes — keep them scoped; a global redesign introducing page-level data-state wrappers could create double matches in e2e locators.
- AdmissionProgress only renders when session != null — error/invalid/needsLogin-before-preview states show no progress strip; consumed-token needsLogin (no preview fetched) also has session=null. A redesign that always shows the stepper changes observable DOM and possibly e2e text matches ('绑定账号截止' appearing where it shouldn't). Also the 60s interval clock and Math.ceil remaining-time strings ('已超时') are unit-visible copy.
- Browser-return refresh whitelist (797-814): only needsLogin/accountMismatch/error (and stale 'loading') states reload the session on focus/pageshow/visibility; ready/linked/approved deliberately do NOT (would abort in-progress child flows). pageshow additionally honors event.persisted (bfcache). Broadening this 'to be safe' would re-fetch and could reset the linked tab state mid-flow.
- buildAdmissionReturnURL strictness (admissionToken.ts:26-42): throws for any non-/verify/:code path and strips query/hash; it is called synchronously in template-bound handlers and in refreshAdmissionAuthState — a rewrite rendering this component on other routes (e.g. previews) will throw.
- Lazy import + layout 'none': the route uses lazyLoad and renders without the app chrome; AdmissionShell IS the page chrome (its own <main>). Moving shell markup into a layout or adding a second <main> changes semantics/a11y (aria-label='认证上下文', '入群认证进度' landmarks).
- errorMessage is effectively constant today (applyError always resets it, 489-491); wiring real API messages into the generic error panel would change copy assertions ('认证链接暂时无法打开' absence on invalid state).
- Clipboard fallback: copyReissueCommand explicitly throws when navigator.clipboard?.writeText is missing and shows the failure toast — both toast strings are e2e-matched via regex alternation, so keep both outcomes reachable.
