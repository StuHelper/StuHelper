# start-page-and-shared-panels

## summary
JoinStartPage.vue (/start, join.stuhelper.com only, lazy-loaded with layout:"none") is a 6-state orchestrator (loading/needsLogin/needsStudentVerification/needsQQBinding/ready/loadFailed) that bootstraps the auth session with force:true, then reads the verification store (fetchStatus, conditionally fetchSchools) to decide which embedded panel to show. It embeds two SHARED panels in non-standalone mode: StudentVerificationPanel (standalone=false, load-on-mount=false, redirect-after-verification=false, @verified -> reload readiness) and QQBindingPanel (standalone=false, load-on-mount=false, @bound -> reload readiness). Both panels are also mounted standalone (all default props) by /user/student-verification (StudentVerificationPage.vue) and /user/qq-binding (QQBindingPage.vue), so any restyle must be join-context-scoped or wrapper-based. StudentVerificationPanel contains a multi-branch form (academic-email OTP with 300ms-debounced academic DB match, LDAP, manual dynamic fields) plus verified/pending/rejected status cards; QQBindingPanel contains bound/unbound cards, binding-code generation, clipboard copy with 1600ms feedback reset, and 3000ms status polling. Both unit tests (joinStartPage.test.ts, studentVerificationPage.test.ts) and e2e tests (auth-callback-and-admission.spec.ts, user-verification.spec.ts) assert heavily on data-attributes, Chinese heading text, button names, and two CSS class names.

A naive rewrite using watchDebounced without the runID guard reintroduces stale-response overwrites of form.email; tests advance timers by exactly 300ms so the delay constant is pinned

Order/duplication matters for the 'clears derived email and disables submit' unit test (l.310-316) — consolidating watchers must preserve net effect including consent reset on school change
- OTP request button is gated by aria-disabled + click-time toast, NOT :disabled (only submitting disables it) — converting it to a hard-disabled button breaks the unit/e2e tests that CLICK it while blocked and expect toast '请先输入学号和姓名。' and zero API calls
