# design-system-and-app-shell

## summary
The design foundation is Tailwind CSS v4 (via @tailwindcss/vite, NO tailwind.config.js or PostCSS config) with the entire design system defined inline in /Users/zxy/Code/StuHelper/clients/web/src/styles/tailwind.css: an @theme block (blue #5b7cf7 / pink #e87aac "蓝粉社区风" palette, lavender bg layers, glass tokens, 18 keyframes) plus a dual dark-mode token override ([data-theme="dark"] attribute block AND a duplicated prefers-color-scheme media block for "system" mode). A small TS mirror lives in src/design-system/ (tokens.ts, rating.ts) with a unit test pinning 'var(--color-rating-N)' output. Glassmorphism is already established app-wide (.glass-card utility, ui/Card.vue glass variants, bg-bg-glass/backdrop-blur-* utilities across header/menus/cards) — but the admission module deliberately uses NONE of it: all 10 admission views ship scoped CSS or raw Tailwind classes with a hardcoded light-only slate/teal palette (#0f172a/#475569/#0f766e), use shadcn-style Button/Dialog/Input that also hardcode slate, and have zero i18n (all copy is hardcoded Chinese; vue-i18n has no admission namespace). Admission routes render with layout:'none' (no AppShell) behind the global page Transition, keyed by route name. Missing infrastructure for a glassmorphism rewrite: no webfonts actually loaded (Inter/JetBrains Mono are token-only fallbacks), no cn()/tailwind-merge/cva utility, no useReducedMotion composable, token-unaware shadcn primitives with no dark variants, no focus-trap/scroll-lock in Dialog, glassEffects TS values out of sync with CSS, and no admission entry in any locale file.

## rewrite_risks
- Dark-mode landmine: moving admission from hardcoded slate to design tokens implicitly opts it into dark mode (theme store runs on join host via App.vue:36; tokens flip via data-theme + the prefers-color-scheme system block). Current admission UI is opaque light-only. The architect must explicitly decide: pin admission to light (e.g., force data-theme handling or non-token colors) or design+test both themes; e2e screenshots/copy tests today implicitly assume light
- Token edits require 3-way sync: any new/renamed CSS custom property must be added to the light @theme (tailwind.css:11+), the [data-theme="dark"] block (:230+), AND the duplicated @media (prefers-color-scheme: dark) block (:296+); missing the third silently breaks 'system' dark users — historical bug pattern: --shadow-focus-ring exists in [data-theme=dark] (:291) but is ABSENT from the media-query block (it ends at :357 with glow-accent), so system-dark users already get the light focus ring; don't replicate
- Tailwind v4 derives utility names from token names (bg-bg-glass, text-text-primary, duration-base, ease-smooth, z-[var(--z-dropdown)], animate-fade-in): renaming any @theme token breaks scattered class usage app-wide with zero build error — grep before renaming; admission rewrite should ADD tokens, not rename
- routeViewKey reuse (App.vue:42-51): admission-token route is keyed by name, so /verify/A -> /verify/B does NOT remount AdmissionPage; a rewrite that initializes state only in onMounted (not watching route.params.code) will show stale state on code change
- Class-as-test-selector coupling: button.join-start-primary-button / button.join-start-secondary-button (joinStartPage.test.ts:91,94) and all data-state/data-admission-* attributes must be carried onto the new markup verbatim; the data-* hooks are cheap to preserve, the class names are easy to lose when switching to shared Button components
- Glass + fixed body::before aurora stacking: admission shell currently paints an opaque background over body::before; a translucent glass shell exposes the global radial-gradient/aurora layer (z-index 0, fixed, animated 25s in dark) — verify backdrop-filter performance on low-end mobile (admission is a QQ in-app/mobile-heavy audience) and that the animated aurora doesn't force constant compositing under large blurred surfaces; prefers-reduced-motion global rule (tailwind.css:586-593) only neuters CSS animations, not gsap/@vueuse/motion JS animation if introduced
- No webfonts are loaded: --font-sans 'Inter' / --font-mono 'JetBrains Mono' silently fall back to system fonts (PingFang SC/Microsoft YaHei for CJK). If the glass redesign adds real font loading, it changes EVERY page (tokens are global) and risks CLS/LCP; if it doesn't, don't design to Inter metrics
- Hand-rolled Dialog a11y gaps to not regress (or to fix knowingly): DialogContent has Teleport-to-body, role=dialog aria-modal, esc via @keydown.esc on the wrapper div (only fires when focus is inside), an X button — but NO focus trap, NO focus restore, NO body scroll lock (useBodyScrollLock exists but is unused here). Swapping to radix-vue Dialog changes teleported DOM structure, focus behavior, and potentially the location of data-admission-bind-confirmation-* attributes the e2e clicks
