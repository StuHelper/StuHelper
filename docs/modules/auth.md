# 统一身份认证模块 (Unified Auth)

## 模块概述

统一身份认证模块是 StuHelper 系统的核心基础设施，负责用户身份验证、账号管理和安全存储。

### 核心目标

- 提供多种认证方式，适应不同场景
- 支持第三方平台（QQ/微信）快捷登录
- 确保敏感数据安全存储
- 为多校扩展预留架构

## 1. 认证层级

### 1.1 认证方式对比

| 认证方式 | 强度 | 实现复杂度 | 适用场景 |
|----------|------|------------|----------|
| LDAP 认证 | ⭐⭐⭐ 强 | 中 | 本校学生首选（推荐） |
| SSO 认证 | ⭐⭐⭐ 强 | 高 | LDAP 不可用时备选 |
| 数据源认证 | ⭐⭐ 中 | 中 | SSO 不可用时备选 |
| 人工审核 | ⭐ 弱 | 低 | 外校学生、特殊情况 |

### 1.2 LDAP 认证流程（推荐）

学校提供 LDAP 服务，可直接验证学号密码，无需模拟登录 SSO。

**LDAP 服务器信息：**
- 地址：`ldap://10.212.24.175`
- Base DN：`ou=people,dc=buaa,dc=edu,dc=cn`

**认证流程：**

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│  用户    │     │ StuHelper│     │  LDAP    │
│ (前端)   │     │  (Agent) │     │  服务器  │
└────┬─────┘     └────┬─────┘     └────┬─────┘
     │                │                │
     │ 1. 提交学号+密码 │                │
     │───────────────>│                │
     │                │                │
     │                │ 2. LDAP Bind   │
     │                │───────────────>│
     │                │                │
     │                │ 3. 认证结果     │
     │                │<───────────────│
     │                │                │
     │ 4. 返回结果     │                │
     │<───────────────│                │
```

**LDAP 命令示例：**

```bash
# 用户认证（Bind 验证）
ldapsearch -x -H ldap://10.212.24.175 \
  -b "ou=people,dc=buaa,dc=edu,dc=cn" \
  -D "uid={学号},ou=people,dc=buaa,dc=edu,dc=cn" \
  -w "{密码}"

# 查询用户信息（需系统账号）
ldapsearch -x -H ldap://10.212.24.175 \
  -b "ou=people,dc=buaa,dc=edu,dc=cn" \
  -D "uid=sslvpn,ou=system,dc=buaa,dc=edu,dc=cn" \
  -w "{系统密码}" \
  "(&(uid={学号})(accountLocked=false)(accountDisabled=false))"
```

**优势：**
- 直接验证，无需模拟浏览器登录
- 响应速度快（毫秒级）
- 可同时获取用户属性信息

### 1.3 SSO 认证流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  用户    │     │ StuHelper│     │  Agent   │     │ 学校SSO  │
│ (前端)   │     │  (后端)  │     │ (校内)   │     │  服务器  │
└────┬─────┘     └────┬─────┘     └────┬─────┘     └────┬─────┘
     │                │                │                │
     │ 1. 提交学号+密码 │                │                │
     │───────────────>│                │                │
     │                │                │                │
     │                │ 2. 创建认证任务  │                │
     │                │───────────────>│                │
     │                │                │                │
     │                │                │ 3. 模拟登录SSO  │
     │                │                │───────────────>│
     │                │                │                │
     │                │                │ 4. 返回认证结果 │
     │                │                │<───────────────│
     │                │                │                │
     │                │ 5. 返回任务结果  │                │
     │                │<───────────────│                │
     │                │                │                │
     │ 6. 认证成功/失败 │                │                │
     │<───────────────│                │                │
     │                │                │                │
```

**关键安全措施：**
- 密码仅在 Agent 内存中短暂存在，认证完成后立即销毁
- Agent 与调度中心通信使用 TLS + PSK 双重加密
- 认证结果不包含原始密码，仅返回成功/失败状态

### 1.3 数据源认证流程

当 SSO 服务不可用时，使用教务系统数据进行验证：

```
输入: 学号 + 姓名 + 身份证后六位
验证: 与教务系统导出数据比对
输出: 认证成功/失败
```

**数据源更新策略：**
- 每学期初通过 Agent 爬取最新学生名单
- 增量更新，保留历史数据
- 数据加密存储，仅用于验证

### 1.4 人工审核流程

```
用户上传证明材料 → 进入审核队列 → 管理员审核 → 通知用户结果
```

**支持的证明材料：**
- 学生证照片
- 录取通知书
- 在读证明

## 2. 账号体系设计

### 2.1 身份标识结构

```
┌─────────────────────────────────────────────────────┐
│                    用户账号                          │
│  ┌───────────────────────────────────────────────┐  │
│  │           主身份 (Primary Identity)            │  │
│  │  ┌─────────────┐  ┌─────────────────────────┐ │  │
│  │  │  school_id  │  │      student_id         │ │  │
│  │  │  (学校ID)   │  │       (学号)            │ │  │
│  │  └─────────────┘  └─────────────────────────┘ │  │
│  └───────────────────────────────────────────────┘  │
│                         │                           │
│                         ▼                           │
│  ┌───────────────────────────────────────────────┐  │
│  │         第三方绑定 (OAuth Bindings)            │  │
│  │  ┌──────────┐  ┌──────────┐  ┌──────────┐    │  │
│  │  │    QQ    │  │   微信   │  │  GitHub  │    │  │
│  │  │ (可选)   │  │  (可选)  │  │  (预留)  │    │  │
│  │  └──────────┘  └──────────┘  └──────────┘    │  │
│  └───────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

### 2.2 绑定规则

| 规则 | 说明 |
|------|------|
| 唯一性 | 一个学生身份只能绑定一个 QQ、一个微信 |
| 解绑限制 | 解绑需人工审核或等待 30 天冷却期 |
| 防交易 | 频繁解绑/绑定触发风控，账号冻结 |

### 2.3 多校支持

通过 `school_id` 字段区分不同学校：

```sql
-- 学校配置表
CREATE TABLE schools (
    id          SERIAL PRIMARY KEY,
    code        VARCHAR(20) UNIQUE NOT NULL,  -- 如 'buaa', 'bit'
    name        VARCHAR(100) NOT NULL,        -- 如 '北京航空航天大学'
    sso_config  JSONB,                        -- SSO 配置
    created_at  TIMESTAMPTZ DEFAULT NOW()
);
```

## 3. 安全存储方案

### 3.1 敏感数据分类

| 数据类型 | 敏感级别 | 存储方式 |
|----------|----------|----------|
| 用户密码 | 🔴 极高 | **禁止存储**，仅内存中转 |
| 身份证号 | 🔴 极高 | AES-256-GCM 加密 |
| 手机号 | 🟠 高 | AES-256-GCM 加密 |
| 学号 | 🟡 中 | AES-256-GCM 加密 |
| 昵称 | 🟢 低 | 明文存储 |

### 3.2 加密方案

```
┌─────────────────────────────────────────────────────┐
│                  密钥管理架构                        │
│                                                     │
│  ┌─────────────┐      ┌─────────────────────────┐  │
│  │   腾讯云    │      │      应用服务器          │  │
│  │    KMS     │◄────►│  (内存中持有 DEK)        │  │
│  │  (主密钥)   │      │                         │  │
│  └─────────────┘      └───────────┬─────────────┘  │
│                                   │                 │
│                                   ▼                 │
│                       ┌─────────────────────────┐  │
│                       │      PostgreSQL         │  │
│                       │  (存储加密后的数据)      │  │
│                       └─────────────────────────┘  │
└─────────────────────────────────────────────────────┘

KEK (Key Encryption Key): 托管于腾讯云 KMS
DEK (Data Encryption Key): 由 KEK 加密后存储，运行时解密到内存
```

### 3.3 加密字段实现

```go
// 加密存储示例 (Go)
type User struct {
    ID              uint64    `gorm:"primaryKey"`
    StudentIDCipher []byte    `gorm:"column:student_id_cipher"` // 加密后的学号
    IDCardCipher    []byte    `gorm:"column:id_card_cipher"`    // 加密后的身份证
    PhoneCipher     []byte    `gorm:"column:phone_cipher"`      // 加密后的手机号
    Nickname        string    `gorm:"column:nickname"`          // 明文昵称
}

// 加密函数
func EncryptField(plaintext string, dek []byte) ([]byte, error) {
    block, _ := aes.NewCipher(dek)
    gcm, _ := cipher.NewGCM(block)
    nonce := make([]byte, gcm.NonceSize())
    io.ReadFull(rand.Reader, nonce)
    return gcm.Seal(nonce, nonce, []byte(plaintext), nil), nil
}
```

## 4. 会话管理

### 4.1 Token 设计

采用 JWT + Redis 双重验证：

```
┌─────────────────────────────────────────────────────┐
│                   JWT Token 结构                     │
├─────────────────────────────────────────────────────┤
│ Header:  { "alg": "HS256", "typ": "JWT" }           │
├─────────────────────────────────────────────────────┤
│ Payload: {                                          │
│   "sub": "user_id",                                 │
│   "school": "buaa",                                 │
│   "exp": 1704067200,                                │
│   "jti": "unique_token_id"                          │
│ }                                                   │
├─────────────────────────────────────────────────────┤
│ Signature: HMACSHA256(base64(header) + "." +        │
│            base64(payload), secret)                 │
└─────────────────────────────────────────────────────┘
```

### 4.2 Token 生命周期

| Token 类型 | 有效期 | 存储位置 |
|------------|--------|----------|
| Access Token | 2 小时 | 客户端内存/LocalStorage |
| Refresh Token | 7 天 | HttpOnly Cookie |
| 会话状态 | 7 天 | Redis |

### 4.3 Token 刷新流程

```
1. Access Token 过期
2. 客户端携带 Refresh Token 请求刷新
3. 服务端验证 Refresh Token 有效性
4. 检查 Redis 中会话状态
5. 签发新的 Access Token
6. (可选) 轮换 Refresh Token
```

## 6. 错误码定义

| 错误码 | 说明 |
|--------|------|
| `AUTH_001` | 学号或密码错误 |
| `AUTH_002` | SSO 服务暂不可用 |
| `AUTH_003` | 认证任务超时 |
| `AUTH_004` | 账号已被冻结 |
| `AUTH_005` | Token 已过期 |
| `AUTH_006` | 绑定关系已存在 |
| `AUTH_007` | 解绑冷却期未结束 |
