下面是一份**“不提前介绍 StuHelper、不引导具体方案”**的问卷设计，目标是：
**真实摸清同学们在校园里的信息获取痛点与真实需求**，而不是让他们顺着你的产品思路作答。

整体原则：

* 不出现 “StuHelper / 平台 / 对象 / 订阅” 等词
* 只问**现在怎么做 + 有多痛 + 希不希望被解决**
* 多用“行为型问题”，少用“你想要什么功能”
